## Context

ADR-018 kept the cage nixcage's and took four primitives from it. ADR-019
gave every factory a machine of its own, ADR-040 built the declaration into
that machine's image, and ADR-037 put every cage on a private bridge. What
nixcage supplies on this branch is now three things: one nspawn line per
session (`enter`), a uid allocator (`uid`), and a dataset helper (`storage
ensure`), plus its host module's userland profile. Its shared VM, `exec`
transport, devShell selection, direnv and git worktree resolution are unused
here. Each of the two options this branch added to `enter` was a lock bump
in two repositories for a flag that NixOS containers already have.

NixOS declarative containers (`containers.<name>`) are systemd-nspawn
containers declared in the machine's own configuration, built into the same
image. They have what ADR-037 asked nixcage for: `privateNetwork` with
`hostBridge` and `localAddress` is the bridge and the address, `privateUsers`
is the uid block, `bindMounts` are the binds, `ephemeral` is a fresh root per
start. The roles are known when the image is built, which is the one fact a
declarative container needs and the one ADR-040 supplies.

## Decision

**1. One `containers.<role>` per declared role, and one for the decider,**
in the machine's configuration, generated by `lib.factory` from the same
declaration the bridge plan and the bus users are generated from. A cage's
address, its veth and its uid block are declared where its name is.

**2. What was a session's argv becomes the container's configuration.** The
role's profile is the container's `environment.systemPackages` alongside pi
and the floor; the guidance, the credentials and pi's directory are
`bindMounts` read-only; the `CAGEWORKS_*` environment is the unit's. The
worktree is a `bindMounts` entry onto the role's dataset. Nothing is composed
at session start, so `seam.bats` asserts the generated container
configuration instead of an argv.

**3. A session is `nixos-container run <role> -- pi --mode rpc`,** started
and restarted by the executor as before (ADR-035 point 4 as amended). The
container itself stays up between sessions; a session is a process in it.

**4. Uids are declared, not allocated.** Each role's block is a fixed range
in the machine's configuration, derived from its position in the
declaration, so `nixcage-container uid` has no caller. A dataset per role is
a `fileSystems` entry made by the storage unit that makes the pool, so
`storage ensure` has none either. The daemon socket is simply not bound.

**5. nixcage leaves the flake.** No input, no lock bump, no ADR-018 seam. The
userland floor becomes the container's own package list.

## Consequences

Each cage is a NixOS with its own systemd: slower to start than a bare
nspawn line, and a rebuild of the machine when a role is added, which ADR-040
already made the normal path. A person entering by hand becomes
`nixos-container root-login` or `run`, with the agent forwarded by the
executor's transport rather than by nixcage's. What is deleted:
`modules/machine-plan.sh`'s argv composition, `role-worktree.sh`'s ACL
dance (a bind mount of a dataset the role owns needs none), `signing.sh`'s
binds become mounts, `tests/command/seam.bats` becomes an evaluation test of
the generated containers, and the two nixcage commits this branch made
become dead code upstream. ADR-018, ADR-028, ADR-030 and nixcage's ADR-011
are superseded when this is done.

Not before `tests/manual/parity.sh` passes on the design as it stands: a
cage change under a factory that has never run end to end is two unknowns
at once.

## Verification

`tests/command/guest_services.bats` gains scenarios per container: address,
uid range, mounts, packages and environment as the declaration implies.
`tests/manual/isolation.sh` passes unchanged, since it asks the bridge and
the proxy and not the cage. `tests/manual/parity.sh` passes unchanged.
